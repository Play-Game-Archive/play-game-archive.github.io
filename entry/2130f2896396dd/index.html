档案卡片

Shunyu Yao

姚顺雨

简介

姚顺雨（Shunyu Yao）是研究语言模型智能体、推理与交互式任务的计算机科学研究者。他参与提出 ReAct、Tree of Thoughts、Reflexion 与 CoALA，并参与建设 WebShop、SWE-bench、SWE-agent 和 τ-bench。这些工作把语言模型研究的对象从单次回答扩展到持续行动：系统怎样观察环境、组织记忆、调用工具、检验结果，以及在失败之后改变下一步选择。

他的职业经历须依材料时间辨认：最后更新于2025年2月的个人主页记录了普林斯顿博士研究、导师 Karthik Narasimhan 以及当时在 OpenAI 的研究；2026年的 CL-bench 和 HY-Embodied-0.5 原始研究则将他的工作置于腾讯混元及具身模型团队中。后者是核实近期研究归属的直接依据，旧主页不宜继续充当现职证明。个人主页、CL-bench 原始论文、HY-Embodied-0.5。

一、研究对象：能做事的语言模型

姚顺雨的代表工作有一个连续的问题意识：语言表达能力如何进入行动过程。问答任务可以在生成文本后结束，购物、修复软件、操作虚拟房间或协助用户却需要多轮交互。第一步行动会改变后续可见信息；用户的目标可能不完整；工具可能返回错误；系统还必须判断是否已经完成。把每轮输出分别评分，容易遗漏这些跨步骤依赖。

这里的智能体通常由基础模型、提示、外部状态、工具接口、记忆和执行程序共同组成。模型可能保持参数不变，整体系统仍能因控制流程而改变能力。模型知识、推理预算、搜索策略、接口与环境支持，以及作者之间的合作，共同形成了系统表现。姚顺雨的重要贡献是在多个合作项目中反复把这些系统要素变成可实验的问题。

他的研究也使游戏与现实任务之间出现可比较的结构。文字冒险、家庭模拟和数字益智题提供低成本、可重置的反馈；软件仓库和业务数据库则提供更贴近实际工作的约束。它们各自暴露不同能力，不能只用“会玩游戏”概括全部研究，也不能从某种封闭环境成功直接推出一般社会行动能力。

其博士论文题为《Language Agents: From Next-Token Prediction to Digital Automation》，以语言智能体连接预测模型与数字自动化；本人旧主页也列 Computer-Using Agent 和 Deep Research 为参与项目。这些项目列名证明公开研究经历，不用于推断所有组件的个人职责。本人研究目录。

二、WebShop：把语言要求落实到一连串选择

2022年提出的 WebShop 是模拟电商环境，商品来自现实数据，任务用自然语言描述购买要求。智能体需要搜索、浏览、辨认属性、选择规格并完成模拟购买。研究把语言理解放入决策链：理解“便于携带且符合某种尺寸”必须影响查询词、筛选和最后选择，而不是只在答案中复述要求。WebShop 论文。

环境设计的重要之处是保留组合约束与信息噪声。一个候选商品可能只满足部分条件；页面内容可能很多，真正相关的属性很少；最早的搜索词也可能需要改写。这使任务既包含检索，又包含计划。论文使用人类示范、模仿学习、强化学习以及预训练模型建立比较，而不是只展示单条成功轨迹。

从这一设置可见，智能体的目标应以环境结果描述。说“我找到了合适商品”和确实选中正确规格是两回事。模拟购物仍省略了真实支付、动态库存和交易责任；它的价值在于提供可控实验场，检验语言条件怎样进入行动，而不是证明系统已经可以无监督经营真实账户。

三、ReAct：让推理与观察交替发生

ReAct 首先在2022年预印本中提出，2023年发表于 ICLR。其名称连接 reasoning 与 acting。基本流程是让模型在任务中交替组织推理和调用动作，动作返回观察后再更新计划。知识问答中可以查询外部资料；交互任务中可以检查环境并采取下一步。姚顺雨是第一作者，论文由多个机构研究者合作完成。ReAct 原始论文。

这种安排改变了错误的传播方式。完全依赖内部知识的推理链，可能在一个错误前提上继续推演；外部观察为修正提供机会。另一方面，盲目连续调用工具也会浪费步骤，推理可以帮助决定现在缺少什么信息、何时应搜索、何时可以行动。两者的结合把“解释答案”推进为“管理求解过程”。

ReAct 的可读轨迹有实际审计价值，但不能直接当作模型全部内部计算的忠实记录。文本理由仍可能不完整，工具返回也可能错误或带有恶意指令。更强的系统设计需要区分外部数据与授权指令，并用执行结果判断任务进度。可读性、因果解释和可靠性是相关却不同的指标，这也是理解该方法影响时必须保留的区分。

四、Tree of Thoughts：把一次生成扩展为搜索

Tree of Thoughts 于2023年提出并发表于 NeurIPS。它把中间的、有一定意义的文本步骤看作“思维”节点，生成多个候选，对候选进行评价，并在树状空间中搜索、前瞻或回退。原始实验包括24点、创意写作和小型填字题，检验早期选择会影响后续可行性的任务。Tree of Thoughts 论文。

其关键不是让模型把同一段话说得更长，而是允许保留备选路径。24点中一个局部运算即使合法，也可能使余下数字无法组合到目标；搜索程序需要发现这一点并重新选择。语言模型在这里同时提供候选和某种评价，传统搜索则提供控制结构。这显示神经生成与符号式程序能够以模块方式结合。

这种推理也增加计算开销。候选数量、搜索深度、评价次数以及停止条件都会改变结果。若评价者偏好流畅却错误的路径，搜索可能放大偏差；若任务本身有精确验证器，应优先利用它。论文中的历史成功率只属于特定模型和预算，不能作为2026年模型排名。对游戏创作而言，这种方法可启发规划或解谜助手，但实际游戏还要解决实时性、隐藏信息和玩家体验，不能照搬实验树的规模。

五、Reflexion：把失败写入下一轮的上下文

2023年的 Reflexion 探索“语言强化”式改进：智能体执行任务，接收反馈，生成对失败的文字反思，再把反思存入记忆，供后续尝试使用。它通常不在每次失败后更新基础模型权重。相应地，论文中的学习发生在跨尝试的记忆和行动策略层面，而非传统梯度更新层面。

反馈可以来自环境中的成功标志、执行错误或测试，也可以借助额外评价。反思的有效内容应当指出可改变的操作：遗漏了什么前置条件、哪个判断缺乏观察、需要怎样检验。泛泛的“下次更仔细”难以约束后续行为；错误的归因还可能让系统重复一种无效策略。记忆的选择、长度与适用条件因此成为系统的实质部分。

arXiv:2303.11366v4列六位作者，姚顺雨署名末位。不同网页或版本可能展示不同作者表，书目记录应绑定具体版本，不把名单拼接成一个从未发表的版本。Reflexion 与 ReAct 也不是同一个机制：前者重点在尝试之间，后者重点在一次交互过程之内；二者可以组合，但需要分别检验。Reflexion v4。

六、CoALA：为智能体建立可比较的架构语言

CoALA 由 Theodore R. Sumers、姚顺雨、Karthik Narasimhan 与 Thomas L. Griffiths 合作，2023年公开，2024年形成 TMLR 版本。前两位作者注明同等贡献。它借鉴认知科学和符号人工智能，把语言智能体描述为记忆组件、内外部行动空间以及选择行动的决策过程。CoALA 原始论文。

这一框架有助于避免把所有外部文本统称“记忆”。当前工作状态、过去经历、可调用技能和一般知识，在系统中承担不同功能。读取记忆、改变记忆、对环境采取动作也不应混为一次普通生成。分类之后，研究者才能问：性能提升来自增加了经验库，还是检索更准确，或是行动选择更合理。

CoALA 的性质是组织理论和研究框架，并非一个统一实现，也没有用分类本身证明人工系统具有人的意识。其价值体现在问题分解：研究者能够明确指出组件与接口，并针对某个组件做干预。它把语言智能体放回更长的人工智能历史，也帮助理解为何许多看似新颖的系统仍涉及记忆、计划和学习这些持久问题。

七、SWE-bench 与 SWE-agent：环境和界面成为研究变量

SWE-bench 于2023年提出、发表于 ICLR 2024，以真实 Python 项目的问题和对应修复构造评测。给定仓库及问题描述，系统必须产生能够解决问题的代码变化。跨文件依赖、执行环境和回归测试使它超出短函数补全；姚顺雨为合作作者之一。SWE-bench 原始论文。

这里的“真实”指任务来源于实际软件问题。测试集只能检验它实际覆盖的行为；修复可能通过可见测试却引入新缺陷；公开问题也需要处理训练数据污染。解释排行榜必须同时记录数据子集、验证版本、模型、代理程序和资源预算。历史论文的低成功率说明了当时的困难，不能搬到当前作为固定事实。

2024年的 SWE-agent 进一步把 agent-computer interface 设为实验对象。文件浏览、代码编辑、仓库导航和运行测试的工具如何呈现，会影响模型能否保持上下文并纠错。这使接口成为能力的一部分：相同模型面对不同的软件操作入口，可能出现不同表现。由此产生一个对游戏开发工具也有用的判断原则：评估创作智能体时，应把编辑器接口、资源检索和构建反馈与模型本身一起记录。SWE-agent 原始论文。

八、τ-bench：把多次一致成功纳入评价

τ-bench 于2024年公开，研究工具、智能体与用户的动态交互。它提供领域 API、业务规则以及由语言模型模拟的用户，以对话结束后的数据库状态与目标状态进行比较。这样可以检验系统是否真正完成操作，而不仅是输出了一段听起来正确的客服回复。τ-bench 原始论文。

论文特别引入 pass^k，观察同一任务多次运行能否持续成功。它与“多试几次，至少成功一次”的指标强调不同问题。实际服务关心重复执行是否稳定，偶尔极佳而经常失败的系统仍难以使用。用户表达变化、模型随机性和规则遵循都可能造成不一致。

模拟用户为规模化实验提供便利，同时也是模型化假设。若模拟用户总按预设方式合作，就可能低估真实沟通中的误解；若最终状态判定不够细，也可能忽略中间不当动作。因此，多轮任务至少需要最终结果、规则遵循和过程记录三个角度。它们可以共同描述可靠性，单独一个总分难以替代全部信息。

九、2026年的上下文学习与具身研究

CL-bench 将问题转向“从当前上下文学习新知识”。任务要求应用材料中提供的新规则、程序或专业知识，而不是只从长文中找一句话。论文与腾讯混元、复旦大学团队共同署名；姚顺雨在作者表中。研究区分读取信息、套用旧知识和掌握新的局部规则，这对企业工具、游戏规则和个人化助手都重要。CL-bench 论文与团队署名。

这种评测也要求谨慎理解“学习”。在一次上下文中掌握规则，不自动等同于长期改变模型参数；任务结束后知识能否保留，是另一项实验。复杂任务使用细分评判标准，也应检查自动评价的一致性和人工复核。模型是否真的学会一种新规则，需要通过变化条件后的应用检验，而不只看它是否复述定义。

HY-Embodied-0.5 则由腾讯 Robotics X 与混元视觉团队提出，将精细时空感知和具身推理作为基础模型能力，讨论不同规模模型、模态专用计算、后训练与蒸馏。姚顺雨列于团队论文作者中。这一合作研究将相关方法进一步用于物理智能中的视觉理解问题。HY-Embodied-0.5 原始论文。

十、学习、搜索和行动的时间尺度

比较姚顺雨参与的几种架构，可以把“改进”拆成三个时间尺度。一次回答内部，Tree of Thoughts 用搜索保留并比较多个中间解；一次任务内部，ReAct 用观察更新当前计划；多次任务尝试之间，Reflexion 用外部记忆保存失败后的经验。它们都能改变行为，但消耗的资源、保留的信息和可恢复的错误不同。

搜索树中的回退，只是放弃一个尚未执行的候选，不会造成环境中的实际损失。现实工具行动却可能已经改写文件、发送消息或改变账户状态，无法通过删除一段推理恢复。将搜索方法接入可执行智能体，需要明确哪些节点是模拟，哪些节点已发生。由此产生的状态管理、事务边界和授权问题，不能由一句“让模型再想一遍”解决。

记忆也需要适用范围。一条“先检查容器是否打开”的经验可能跨多个家庭任务有用；某个页面布局对应的点击次序却可能很快过时。将两者无差别检索，会使有价值的经验与偶然细节竞争上下文。Reflexion 的思想进一步提出可研究问题：什么内容应当保存，何时应更新，怎样让后续观察推翻旧反思。它的评价不应只看记忆是否越来越长，还要看同类错误是否减少、新任务是否受益。

CoALA 的架构语言则帮助记录上述差异。工作记忆中的当前计划、保存过往经历的记录、可执行程序技能，以及基础模型中的知识，并不是相同存储。它们可能相互转换：反思可以形成规则，成功程序可以成为技能，失败观察可以触发新搜索。研究贡献在于解释这些转换怎样影响行动，而不是把所有组件加在一起便称为更像人脑。

十一、评价智能体时，究竟固定了什么

这些工作提出的基准分别固定了不同条件。WebShop 用商品与任务约束观察语言落地，SWE-bench 用真实软件问题和测试观察修复，τ-bench 用动态用户、领域政策与数据库状态观察可靠执行。它们之间的分数没有自然换算关系。购物中一次错误规格、软件中一次测试失败和业务中一次越权操作，所代表的损失也不相同。

对同一环境，模型调用数、上下文、候选数量和执行时间都会影响成绩。一个搜索代理比单次生成表现好，可能说明组织计算有效；若它调用了数十倍资源，则还需要在相同预算下比较。更清楚的实验可以同时呈现成功率随预算变化的曲线，避免把复杂系统的收益简单解释成基础模型更聪明。

动态工具与线上模型还会使复现实验受到时间影响。模型服务升级、网页改版或软件依赖变化，可能让同一提示得到不同结果。保存轨迹、模型版本、环境快照及最后状态，能够把失败定位到具体环节。它们不是附带的工程记录，而是支撑“某种控制方式带来了改进”这一论断的证据。

最后，成功的判定应超出代理自己的总结。系统可以自信地宣称修复完成，但程序测试和实际差异可能显示另一种状态；对话可以自然结束，数据库却没有正确更新。姚顺雨这条研究路线的重要推进，正是持续把最终判断交回环境反馈、测试和状态，并进一步研究这些反馈本身何时可靠。

十二、贡献、影响与尚待解决的问题

这些工作共同改变了智能体研究的实验单位。输出的一句话，逐渐让位于带状态的行动轨迹；单次解题，让位于多次尝试和长期记忆；孤立模型，让位于模型、工具、接口及环境共同构成的系统。姚顺雨在方法、环境、架构和评测四个层面均参与了这一变化，其影响不能只归结为一个提示词技巧。

与此同时，几组问题仍须分别回答：外部反馈是否可信；推理文本是否帮助行动；更多搜索是否值得额外成本；记忆能否避免传播错误；任务成功是否包含了授权与规则；评测环境能否代表部署环境。这些问题可以通过消融、跨环境测试、状态审计和多次重复实验逐项研究。它们也说明，开放游戏中的自主角色、开发助手和现实业务代理共享一些技术结构，各自仍有独立的评价标准。
