# 简介

论文利用游戏自身的源程序和一个棋盘，通过反演图块重写规则，从已解状态生成新的可解起始关卡。作者限定了所支持的行为树结构，在Peg Solitaire、Merge、Sokoban与TwoDoor四种游戏中枚举并核查关卡，再与正向枚举比较。论文同时保留这一方法对语言与棋盘结构的限制，并把更复杂游戏、设计者研究和理论正确性证明列为未来方向。

## Abstract

Procedurally generating levels for games often involves writing custom algorithms or providing large amounts of levels to learn from. In this work, we explore an approach to general video game level generation using a game’s source program along with a single level, based on the concept of program inversion. Given the forward program for a game, we produce an inverted program in the same language that essentially runs the game backward. Starting from a solved level (which can be found searching with the forward program on a level), the inverted program can be run to generate variations on the level. We look at simple games written in a domain-specific rewrite-based language for describing tile- and turn-based games, where a single player repeatedly makes deterministic choices until they win. We verify that the level variations created by the inverted program can be solved by the original forward program.

<!-- translation -->
## 摘要

为游戏程序化生成关卡，往往需要编写定制算法，或提供大量关卡供系统学习。本研究基于程序反演的概念，探索一种利用游戏源程序和单个关卡来进行通用电子游戏关卡生成的方法。给定游戏的正向程序，我们用相同语言产生一个反演程序，它实质上会倒着运行游戏。从一个已解关卡出发——可以使用正向程序在一个关卡上搜索，找到这种状态——运行反演程序，就能生成该关卡的变体。我们考察以一种基于重写的领域专用语言编写的简单游戏；这种语言用于描述图块制、回合制游戏，单个玩家在其中反复作出结果确定的选择，直到获胜。我们验证，反演程序产生的关卡变体能够由原来的正向程序解出。

<!-- pair:en:INV00010:heading -->
## 1. Introduction

<!-- translation -->
## 1. 引言

<!-- endpair -->

<!-- pair:en:INV00011:paragraph -->
Procedural content generation (PCG) for creating game content, such as game levels, has become increasingly popular [1]. There are a wide variety of approaches to PCG, with claimed benefits such as various kinds of replayability and tailoring content to players [2].

<!-- translation -->
利用程序化内容生成（PCG）创作关卡等游戏内容，已经越来越普遍[1]。PCG有多种多样的方法，其宣称的好处包括不同形式的可重玩性，以及针对玩家定制内容等[2]。

<!-- endpair -->

<!-- pair:en:INV00012:paragraph -->
However, the majority of PCG techniques require a fair amount of additional work above and beyond the work needed to create a game in the first place. “Classical” rule-, search- and constraint-based approaches require writing custom code just for generating content (e.g., a grammar, a fitness function, or constraints). More recent machine learning and “generative AI” [3] approaches often require large amounts of training data, potentially defeating the purpose of generating content in the first place [4]. If the content being generated is game levels, it is important for them to be completable and solvable by the player, and it is not uncommon to also apply a game-playing agent for testing content (e.g., [5, 6]).

<!-- translation -->
然而，大多数PCG技术都需要在最初制作游戏所需工作之外，再投入相当多的额外劳动。“经典”的基于规则、搜索和约束的方法，需要专门为生成内容编写定制代码，例如语法、适应度函数或约束。较新的机器学习和“生成式AI”方法[3]，往往需要大量训练数据，这可能反而违背最初生成内容的目的[4]。如果生成的是游戏关卡，那么玩家能够完成并解出它们就很重要；人们也常用游戏游玩智能体来测试内容，例如[5,6]。

<!-- endpair -->

<!-- pair:en:INV00013:paragraph -->
With the goal of reducing the amount of additional work needed to generate content for a game, in this work we explore an approach to generating content for a game based on things a designer would need to create for the game anyway: the game’s source code, along with at least one level. This can be considered general video game level generation [7]: generating levels for a whole class of games implemented in description language. Our approach is based on the concept of program inversion: the game’s source code is inverted to create a new program, in the original description language, that undoes player moves in the game. The inverted program can then be run on a solved level to generate new starting levels that we know can be solved by the original program. We call this concept procedural level generation via program inversion.

<!-- translation -->
为了减少为游戏生成内容所需的额外工作，本研究探索一种基于设计者无论如何都需要为游戏创建之物的方法：游戏源代码，以及至少一个关卡。这可以视为通用电子游戏关卡生成[7]，即为使用描述语言实现的一整类游戏生成关卡。我们的方法以程序反演概念为基础：将游戏源代码反演，使用原来的描述语言创建一个新程序，用来撤销游戏中玩家的移动。随后可在已解关卡上运行反演程序，生成新的起始关卡；我们知道，这些起始关卡能够由原程序解出。我们将这一概念称为通过程序反演进行程序化关卡生成。

<!-- endpair -->

<!-- pair:en:INV00014:paragraph -->
In this work we take an initial step in this direction. We use programs written in a small variant of the domain-specific language Tile Rewrite Rule Behavior Trees (TRRBTs) [8]. In this language, 2D grids of tiles, called boards, are used to represent starting levels as well as the current game configuration, and the logic of a game’s program is represented using a behavior-tree like structure, called a tree. Leaf nodes of the tree can change the board by rewriting one pattern of tiles (the left-hand side) with another (the right-hand side), or check for the existence of a pattern of tiles on the board by matching it. We chose this language as inverting the changes to board configuration based on rewrites is straightforward: swap the left and right hand sides of the rule. Additionally, the modularity of the language allows us to limit the structure of supported games, and we do not use the full range of tree and node structures that TRRBTs can support. We limit to games with a simple tree structure: those where a single player repeatedly makes a choice with deterministic consequences until they win.

<!-- translation -->
本研究向这一方向迈出了初步一步。我们使用领域专用语言“图块重写规则行为树”（Tile Rewrite Rule Behavior Trees，TRRBTs）[8]的一个小型变体来编写程序。在这种语言中，由图块构成的二维网格称为棋盘，用于表示起始关卡及当前游戏配置；游戏程序的逻辑则用一种类似行为树的结构表示，称为树。树的叶节点可以把一种图块模式，即左侧，重写为另一种模式，即右侧，从而改变棋盘；也可以通过匹配，检查棋盘上是否存在某种图块模式。我们选择这种语言，是因为反演基于重写的棋盘配置变化很直接：交换规则的左右两侧即可。此外，语言的模块性使我们能够限制所支持游戏的结构；我们并未使用TRRBTs可以支持的全部树和节点结构。我们只处理具有简单树结构的游戏：单个玩家反复作出具有确定后果的选择，直到获胜。

<!-- endpair -->

<!-- pair:en:INV00015:paragraph -->
To generate levels for a game, given the game’s TRRBT code tree and a board, we use the tree to solve the board (if needed — an already solved board can be provided), then invert the tree and run the inverted tree on the solved board to generate new boards. These boards are variations on the original board. These variations maintain certain features from the initial input board as there are elements of the boards that cannot be changed by rewrites (e.g., walls or the dimensions of the board). However, this approach is effective in generating interesting and solvable level variations. While the result of a program inversion with one starting board will have some underlying constants between all levels, these level variations have advantages from requiring many more steps to solve to having more interactive pieces on the board, depending on the game.

<!-- translation -->
给定游戏的TRRBT代码树与一个棋盘，要为它生成关卡，我们先用树解出棋盘——如果需要的话，也可以直接提供一个已解棋盘——再反演树，在已解棋盘上运行反演树，生成新棋盘。这些棋盘是原棋盘的变体。由于棋盘上有些要素不能通过重写改变，例如墙壁或棋盘尺寸，这些变体会保留初始输入棋盘的某些特征。不过，这一方法能够有效生成有趣且可解的关卡变体。虽然从一个起始棋盘进行程序反演，所得全部关卡之间会存在一些底层不变量，但视游戏而定，这些关卡变体可以带来不同优势，例如需要更多解题步数，或在棋盘上具有更多可交互棋子。

<!-- endpair -->

<!-- pair:en:INV00016:paragraph -->
We present the program inversion approach we used for TRRBTs having this structure, and implemented four games: Peg Solitaire (jumping pegs to remove them), Merge (merging neighboring numbers into higher numbers), Sokoban (pushing crates onto targets), and TwoDoor (a simple lock-and-key dungeon). We show empirically that the inverted trees only generate solvable boards, by enumerating them and checking their solvability. We also show that generating boards using an inverted tree compares favorably to a similar approach using only the original (forward) tree.

<!-- translation -->
我们介绍用于这种结构的TRRBTs的程序反演方法，并实现四种游戏：Peg Solitaire（跳过棋子并将其移除）、Merge（把相邻数字合并为更大的数字）、Sokoban（把箱子推到目标位置），以及TwoDoor（简单的锁钥地牢）。我们通过枚举棋盘并检查其可解性，从经验上表明反演树只生成可解棋盘；也表明，使用反演树生成棋盘，与仅使用原始正向树的类似方法相比具有优势。

<!-- endpair -->

<!-- pair:en:INV00017:paragraph -->
This work contributes the general concept of program inversion as an approach to generating content for games from a game’s source code, as well as an exploration of this concept in a domain-specific language, generating levels across several games.

<!-- translation -->
本研究的贡献，是提出把程序反演作为一种从游戏源代码生成游戏内容的方法的一般概念，并在一种领域专用语言中探索这一概念，为多个游戏生成关卡。

<!-- endpair -->

<!-- pair:en:INV00018:heading -->
## 2. Related Work

<!-- translation -->
## 2. 相关工作

<!-- endpair -->

<!-- pair:en:INV00019:paragraph -->
**Procedural Content Generation.** A variety of approaches have been developed for procedural content in games [1]. These range from “classic” techniques, such as constructive- or rule- based (e.g., [9, 10]), to search-based (e.g., [11, 12]), and constraint-based (e.g., [13, 14]) methods. Such approaches generally require implementing a generator in addition to implementing the game itself.

<!-- translation -->
**程序化内容生成。**游戏程序化内容生成已有多种方法[1]，从构造式、基于规则等“经典”技术，例如[9,10]，到基于搜索，例如[11,12]，以及基于约束的方法，例如[13,14]。这些方法通常要求在实现游戏之外，再实现一个生成器。

<!-- endpair -->

<!-- pair:en:INV00020:paragraph -->
Recently, machine learning approaches that can learn from example content have been developed in the area of PCGML [3], as well as “generative AI” [15]. Such approaches can require large amounts of data for training or pre-training, and may not guarantee solvability of generated levels (sometimes relying on an agent test or repair step). Some learning approaches, however, can learn from a single example level (e.g., WaveFunctionCollapse [16] or Sturgeon [17]). These approaches could thus potentially require only the game’s code and an example level to work, as they could learn to generate levels from the example level, and then use the code to check solvability, in a generate-and test framework. Comparing that to our program inversion approach would be interesting future work.

<!-- translation -->
近年来，PCGML[3]及“生成式AI”[15]领域发展了能够从内容示例学习的机器学习方法。这类方法可能需要大量数据进行训练或预训练，也可能无法保证生成关卡的可解性，有时需要智能体测试或修复步骤。不过，一些学习方法能够从单个示例关卡学习，例如WaveFunctionCollapse[16]或Sturgeon[17]。因此，这些方法也可能只需游戏代码和一个示例关卡便可工作：先从示例关卡学习生成关卡，再在生成—测试框架中使用游戏代码检查可解性。将其与我们的程序反演方法比较，会是有趣的未来工作。

<!-- endpair -->

<!-- pair:en:INV00021:paragraph -->
In this work we enumerate all the possible boards found by the inverted tree. This is essentially a form of Exhaustive PCG [18]; however, we do this mainly to confirm the levels’ solvability. Some work has looked at interactively visualizing and filtering such large datasets of generated levels [19].

<!-- translation -->
本研究枚举反演树找到的全部可能棋盘。这实质上是穷尽式PCG[18]的一种形式；不过，我们这样做主要是为了确认关卡可解性。已有研究探索了对这种大型生成关卡数据集进行交互式可视化与筛选[19]。

<!-- endpair -->

<!-- pair:en:INV00022:paragraph -->
**General Video Game Level Generation and Game DSLs.** A number of domain-specific languages have been developed over the years for describing both board and video games, such as Ludii [20], Game Description Language [21], Video Game Description Language [22], Ceptre [23], and PuzzleScript [24]. Some have been used as targets for general video game level generation: that is, given a game’s code in some description language along with a player agent, generate levels for the game [7].

<!-- translation -->
**通用电子游戏关卡生成与游戏DSL。**多年来，人们开发了多种描述棋盘游戏和电子游戏的领域专用语言，例如Ludii[20]、游戏描述语言[21]、电子游戏描述语言[22]、Ceptre[23]和PuzzleScript[24]。其中一些已被用作通用电子游戏关卡生成的目标语言：给定以某种描述语言编写的游戏代码及一个玩家智能体，为该游戏生成关卡[7]。

<!-- endpair -->

<!-- pair:en:INV00023:paragraph -->
One approach in this area approached generating levels for games written in VGDL by translating it into Answer Set Programming [25]. This approach also applied an evolutionary process with agents verifying that levels are solvable. Other work developed a framework for evaluating general VGDL level generators [7]. VGDL has also been used for evaluating general level generators [26].

<!-- translation -->
这一领域的一种方法，把VGDL游戏翻译为回答集程序设计，以生成关卡[25]。该方法还采用进化过程，并由智能体验证关卡可解性。另一项研究开发了评估通用VGDL关卡生成器的框架[7]。VGDL也被用于评估通用关卡生成器[26]。

<!-- endpair -->

<!-- pair:en:INV00024:figure -->
Figure 1: Generic approach to TRRBT program inversion. Forward tree on the left and inverted tree on the right.

<!-- translation -->
图1：TRRBT程序反演的一般方法。左侧为正向树，右侧为反演树。

图内文字汉译：Program: forward，程序：正向；Program: inverted，程序：反演；loop-until-all，循环直至一轮中全部子节点失败；win:1，玩家1获胜；lose:1，玩家1失败；player:1，玩家1；rewrite，重写；match-times:T，模式出现T次；END，终局模式；LEFT与RIGHT，规则左侧与右侧。下标与规则箭头按原图保留。

<!-- endpair -->

<!-- pair:en:INV00025:paragraph -->
PuzzleScript has also been a target for general level generation. For example, one approach has used constructive and search based techniques based on an analysis of a game’s rules [27]. While most prior work in general video game level generation creates levels, our work aims to create a level generator in the original language. Notably, earlier work in TRRBTs [8] generated randomly shuffled levels using the player’s moves from within the tree, but only if the individual moves themselves were reversible.

<!-- translation -->
PuzzleScript也被用作通用关卡生成的目标。例如，一种方法基于游戏规则分析，采用构造式和基于搜索的技术[27]。多数既有通用电子游戏关卡生成研究直接创建关卡；我们的目标则是用原语言创建一个关卡生成器。值得注意的是，早期TRRBTs研究[8]利用树内部的玩家移动，生成随机打乱的关卡，但仅在各次移动本身可逆时才这样做。

<!-- endpair -->

<!-- pair:en:INV00026:paragraph -->
**Game Mechanic Inversion.** Some previous work has looked at inverting moves or mechanics in specific games as a way to ensure the solvability of generated levels. This is a not uncommon approach to generating Sokoban [28] levels, by letting the character pull rather than push crates from a solved configuration (e.g., [29, 30, 31]), as well as similar specific games. A similar approach, that of undoing moves, has also been applied to generating Sudoku number puzzles [32]. Some work on Sokoban has also looked at using reversed moves to solve puzzles, starting from the solution and searching backwards to the start [33]. While usually these works look at specific games, we are looking at a more general technique for a whole category of games.

<!-- translation -->
**游戏机制反演。**一些既有研究把特定游戏中的移动或机制反演，用来保证生成关卡的可解性。在生成Sokoban[28]及类似特定游戏的关卡时，这是一种并不少见的方法：从已解配置出发，让角色拉箱子，而不是推箱子，例如[29,30,31]。类似的撤销移动方法，也曾用于生成数独谜题[32]。一些Sokoban研究还用反向移动来求解谜题，从解开始向起点逆向搜索[33]。这些工作通常研究特定游戏；我们则研究面向一整类游戏的更通用技术。

<!-- endpair -->

<!-- pair:en:INV00027:paragraph -->
**Program Inversion.** The general concept of program inversion [34], roughly speaking, is to derive a program that does the opposite of some given program, mapping outputs back to inputs. A number of approaches to program inversion focus on theoretical proofs of the correctness of the inversion [35], for example of tree traversals [36, 37] or certain types of matrix multiplication [38]. The program inversion concept is promising for programs that naturally pair in this way, such as compression/decompression programs [39].

<!-- translation -->
**程序反演。**粗略地说，程序反演的一般概念[34]，是导出一个与给定程序作用相反的程序，把输出映射回输入。一些程序反演方法关注反演正确性的理论证明[35]，例如树遍历[36,37]或某些矩阵乘法[38]。对于压缩／解压缩这类天然成对的程序[39]，程序反演概念很有前景。

<!-- endpair -->

<!-- pair:en:INV00028:paragraph -->
In some cases a non-deterministic mapping from outputs back to inputs may be acceptable [40] or even desirable. A similar approach to ours, for example, has been used to generate TIFF images for testing implementations of image clients [41]. They use a normalization program to create a normalized representation of an image, and then invert that program and use the inverse program to generate test images. This can be seen as analogous to our approach of using the original (forward) program to solve a level and then the inverse program to generate new levels from that.

<!-- translation -->
在某些情况下，从输出回到输入的非确定性映射也许可以接受[40]，甚至是所希望的。例如，一种与我们类似的方法曾用于生成TIFF图像，以测试图像客户端的实现[41]。它先用归一化程序创建图像的归一化表征，再反演这一程序，利用逆程序生成测试图像。这可以类比于我们先用原始正向程序解出关卡，再用逆程序据此生成新关卡的方法。

<!-- pair:en:INV00029:heading -->
## 3. System Overview

<!-- translation -->
## 3. 系统概述

<!-- endpair -->

<!-- pair:en:INV00030:paragraph -->
Here we describe the approach we take to generating levels based on a game’s source code.

<!-- translation -->
这里介绍我们依据游戏源代码生成关卡的方法。

<!-- endpair -->

<!-- pair:en:INV00031:paragraph -->
**Game Representation.** Our inversion method for level generation uses Tile Rewrite Rule Behavior Trees (TRRBTs) as the underlying game representation [8], although we only support a very specific type of game, and not the full range of games that TRRBTs allow. Games consist of a board and a tree. The board is a 2D array of tiles — strings of characters — that represent the current configuration of a game. A board can have multiple named layers of tiles that are stacked on top of each other. This makes it easier for something like foreground tiles to move over background tiles (e.g. pushing crates over targets in Sokoban, discussed below). Terminology-wise, “board” can be considered the term for a “level” in TRRBTs. A layered 2D array of tiles that does not represent the game board is also called a pattern. A board can also have a result associated with it, either win or lose if the game has ended in one of those outcomes, stalemate if the game has ended without an explicit outcome, or nil if the game is still running.

<!-- translation -->
**游戏表征。**我们的关卡生成反演方法以图块重写规则行为树（TRRBTs）作为底层游戏表征[8]，但只支持很特定的一类游戏，而非TRRBTs允许的全部游戏。游戏由棋盘和树组成。棋盘是图块，即字符串，构成的二维数组，表示游戏当前配置。一个棋盘可以具有多个相互叠放、各有名称的图块层。这使前景图块越过背景图块等操作更容易实现，例如下文Sokoban中把箱子推过目标位置。在术语上，可以把“棋盘”看作TRRBTs中“关卡”的称谓。不代表游戏棋盘的分层二维图块数组，也称为模式。棋盘还可以带有结果值：若游戏已按相应结果结束，则为win或lose；若游戏结束但没有明确结果，则为stalemate；若游戏仍在进行，则为nil。

<!-- endpair -->

<!-- pair:en:INV00032:paragraph -->
The tree determines the logic of the game and makes changes to the board. The tree is run as a behavior tree, with nodes succeeding or failing based on specific conditions for their node type, and returning that information to their parent node, which adjusts its behavior based on its children.

<!-- translation -->
树决定游戏逻辑，并修改棋盘。树按照行为树方式运行：节点根据所属类型的特定条件成功或失败，把这一信息返回父节点；父节点再根据子节点调整行为。

<!-- endpair -->

<!-- pair:en:INV00033:figure -->
Figure 2: Inversion of tree for Peg Solitaire. Forward tree on the left and inverted tree on the right.

<!-- translation -->
图2：Peg Solitaire的树反演。左侧为正向树，右侧为反演树。

图内文字汉译：Peg Solitaire，单人跳棋；forward，正向；inverted，反演；loop-until-all，循环直至一轮中全部子节点失败；win:1，玩家1获胜；lose:1，玩家1失败；player:1，玩家1；rewrite，重写；match-times:1，模式出现1次。棋子、空格与重写方向按原图保留。

<!-- endpair -->

<!-- pair:en:INV00034:figure -->
Figure 3: Forward trees for other games used. For space, rewrite nodes that are rotations of others are omitted.

<!-- translation -->
图3：所用其他游戏的正向树。受篇幅限制，作为其他节点旋转形式的rewrite节点予以省略。

图内文字汉译：Merge，合并；Sokoban，推箱子；TwoDoor，双门；forward，正向；loop-until-all，循环直至一轮中全部子节点失败；win:1，玩家1获胜；player:1，玩家1；rewrite，重写；match-times:0／1，模式出现0／1次；main，主层；trgt，目标层。图中的字符图块、数字与箭头保留原样。

<!-- endpair -->

<!-- pair:en:INV00035:paragraph -->
Both a board and a tree are required for a game to be played. Although in previous work boards were included directly in the tree through a set-board node, in our method, we separated the board from the tree so that we could more easily invert the tree and and allow for different starting boards to be passed into the same tree.

<!-- translation -->
要进行游戏，棋盘和树两者缺一不可。虽然早期工作通过set-board节点把棋盘直接纳入树中，我们的方法将棋盘与树分开，以便更容易反演树，并使不同起始棋盘能够传入同一棵树。

<!-- endpair -->

<!-- pair:en:INV00036:paragraph -->
**Supported Tree Structure and Inversion.** In this work we use only a few node types and require them to be in a particular arrangement. The node types are:

<!-- translation -->
**所支持的树结构及其反演。**本研究只使用少量节点类型，并要求它们按特定方式排列。节点类型如下：

<!-- endpair -->

<!-- pair:en:INV00037:list -->
• loop-until-all: Iteratively runs children in order until all children fail on one iteration. Succeeds if any child succeeds, otherwise fails.

<!-- translation -->
• loop-until-all：按顺序反复运行子节点，直到某一轮中全部子节点都失败。如果任何子节点成功，则成功；否则失败。

<!-- endpair -->

<!-- pair:en:INV00038:list -->
• win and lose: Runs children in order. If any child succeeds, immediately ends the game with the respective result for its associated player; otherwise fails.

<!-- translation -->
• win和lose：按顺序运行子节点。如果任何子节点成功，立即以该节点对应玩家的相应结果结束游戏；否则失败。

<!-- endpair -->

<!-- pair:en:INV00039:list -->
• player: All children of a player node must be rewrite nodes. If any LEFT pattern of a child is present in the current board, the player can chose one LEFT to be replace with its associated RIGHT and the player node succeeds. Fails if there are no LEFT patterns present.

<!-- translation -->
• player：player节点的全部子节点都必须是rewrite节点。如果任一子节点的LEFT模式出现在当前棋盘上，玩家可以选择一个LEFT，用其对应的RIGHT替换，此时player节点成功。若不存在任何LEFT模式，则失败。

<!-- endpair -->

<!-- pair:en:INV00040:list -->
• rewrite: Contain the rewrites, where the associated LEFT can be replaced with the associated RIGHT. In this work, these are always the child of a player node and so not run directly.

<!-- translation -->
• rewrite：包含重写操作，可用对应的RIGHT替换LEFT。本研究中，这些节点始终是player节点的子节点，因此不会被直接运行。

<!-- endpair -->

<!-- pair:en:INV00041:list -->
• match-times: Succeeds if its pattern is present in the current board its associated number of times, otherwise fails.

<!-- translation -->
• match-times：如果其模式在当前棋盘中出现的次数符合节点所关联的次数，则成功；否则失败。

<!-- endpair -->

<!-- pair:en:INV00042:paragraph -->
Our program inversion approach takes a tree representing a game’s (forward) logic as an input. These trees are required to fit the specific tree structure shown in Figure 1(left). This structure essentially represents a game loop that alternates checking for a win and the player making a move. The root is a loop-until-all node with two children. The first child of this loop is a win node that has a child match-times node that succeeds if a pattern END is matched on the board T times. The second child of loop-until-all is required to be the player node with a series of N rewrite nodes with patterns LEFT_i and RIGHT_i, 1 ≤ i ≤ N as children. Note that in this structure, checking for a win before the player moves allows starting from a board that is already solved.

<!-- translation -->
我们的程序反演方法以表示游戏正向逻辑的树作为输入。这些树必须符合图1左侧所示的特定结构。该结构实质上表示一个游戏循环：交替检查是否获胜和让玩家移动。根节点是一个具有两个子节点的loop-until-all节点。该循环的第一个子节点是win节点，它又有一个match-times子节点；当模式END在棋盘上匹配T次时，这个子节点成功。loop-until-all的第二个子节点必须是player节点，其子节点是一系列共N个rewrite节点，具有模式LEFT_i与RIGHT_i，其中1≤i≤N。请注意，在这种结构中，先检查获胜再让玩家移动，因此允许从一个已经解出的棋盘开始。

<!-- endpair -->

```text
foreach b ∈ boardsGen:
    assert(solve(tree, b) ≠ nil)
end
```

<!-- pair:en:INV00045:paragraph -->
The inverted version of such a tree is shown in Figure 1(right). The root remains a loop-until-all node, with the order of the children reversed. First is the player node, with the order of its rewrite children reversed, and the sides if these individual rewrite nodes reversed, and so that RIGHT_i is on the left and LEFT_i is on the right. This allows individual rewrites to be done backward. Second is a lose node, taking the place of the win node and its match-times child and associated END. A lose node is used so that the inverted game won’t output a board that is already winning. Note that here losing is checked for after making a move, as the inverted tree presumes that it is starting from a board that won from the forward tree.

<!-- translation -->
这种树的反演版本见图1右侧。根节点仍为loop-until-all，但其子节点顺序颠倒。首先是player节点，其rewrite子节点的顺序也颠倒；各个rewrite节点的两侧同样颠倒，使RIGHT_i位于左侧，LEFT_i位于右侧。这样就可以反向执行各次重写。其次是lose节点，它取代win节点，同时承接其match-times子节点及关联的END。使用lose节点，是为了避免反演游戏输出一个已经获胜的棋盘。注意，这里是在移动之后检查失败，因为反演树预设自己从一个在正向树中已经获胜的棋盘开始。

<!-- endpair -->

<!-- pair:en:INV00046:paragraph -->
The resulting inverted tree can be run on a solved board, and each board that would be presented to the player will be a solvable starting board for the game. This can be used to generate new levels that are variations on the same underlying level structure.

<!-- translation -->
所得反演树可以在已解棋盘上运行，而每个将被呈现给玩家的棋盘，都会成为该游戏的一个可解起始棋盘。这可用于生成新关卡，它们是同一底层关卡结构的变体。

## 4. 评估

<!-- endpair -->

<!-- pair:en:INV00048:paragraph -->
Here we describe evaluations of the program inversion approach. Game trees and enumerated boards from the evaluation can be found at https://osf.io/er5wh/.

<!-- translation -->
这里介绍对程序反演方法的评估。评估所用游戏树和枚举棋盘可在https://osf.io/er5wh/获取。

<!-- endpair -->

<!-- pair:en:INV00049:paragraph -->
**Inverted Enumeration of Boards.** To empirically verify that the inverted trees generate only boards that can be solved, and to gather descriptive information on the generated boards, we enumerate all boards that are produced by an inverted tree, starting from a solved board.

<!-- translation -->
**棋盘的逆向枚举。**为了从经验上验证反演树只生成可解棋盘，并收集生成棋盘的描述性信息，我们从已解棋盘出发，枚举反演树产生的全部棋盘。

<!-- endpair -->

<!-- pair:en:INV00050:paragraph -->
The overall approach is shown in Algorithm 1. It starts by taking the (forward) tree for a game in the structure described above and a solvable starting board for the game. The function solve runs a breath-first search with the forward tree until it reaches a solved board that wins the game; this also associates the number of steps it took to solve with the board. Then invert produces the inverted tree as described above. Next, enumerate finds all boards reachable by the inverted tree, starting from the solved board; each enumerated board also gets associated with the number of steps it took to reach. From these enumerated boards, we keep only those that took at least one step to reach (so they are not the solved board from which inverted enumeration began) and either have not ended or ended in a stalemate. These enumerated boards are checked by asserting that it is possible to win each of then using the forward tree.

<!-- translation -->
总体方法见算法1。首先取得符合上述结构的游戏正向树，以及该游戏的一个可解起始棋盘。solve函数用正向树进行广度优先搜索，直到到达一个获胜的已解棋盘；同时把求解所需步数与该棋盘关联。随后，invert按前述方法产生反演树。接着，enumerate从已解棋盘出发，找出反演树能够到达的全部棋盘，并把到达各棋盘所需的步数与其关联。从这些枚举棋盘中，我们只保留至少经过一步才能到达的棋盘——因此不包括逆向枚举开始时的已解棋盘——而且它们要么尚未结束，要么以僵局结束。最后，通过断言每一个枚举棋盘都可以利用正向树获胜，检查这些棋盘。

## 5. Discussion

<!-- translation -->
## 5. 讨论

<!-- endpair -->

<!-- pair:en:INV00061:paragraph -->
Checking that all the boards enumerated by the inverted tree when starting from a solved board are themselves solvable shows, empirically in the cases that were tried, that running the inverted tree will always result in a solvable board that could thus be used in a game.

<!-- translation -->
检查从已解棋盘出发由反演树枚举出的全部棋盘，确认它们自身都可解，这在所尝试的情形中从经验上表明：运行反演树总会产生一个可解棋盘，因此可以用于游戏。

<!-- endpair -->

<!-- pair:en:INV00062:paragraph -->
One potentially useful feature of the approach is that it works from a solved board or a starting board. This provides flexibility, as a designer can either use a starting board (which they may already have if they are working on a game) and get variations on that board, or start from a desired solution and generate boards directly from that.

<!-- translation -->
这一方法一个可能有用的特点，是既可从已解棋盘，也可从起始棋盘工作。这带来了灵活性：设计者可以使用一个起始棋盘——如果正在制作游戏，他们可能已经有这样的棋盘——获得其变体；也可以从期望的解出发，直接生成棋盘。

<!-- endpair -->

<!-- pair:en:INV00063:paragraph -->
We also found that, in comparison to just forward enumeration from a solvable board, inverse enumeration find more boards. When starting from a solved board there are, unsurprisingly, no new boards to be found. But even in the games starting from unsolved boards, inverted enumeration is able to find a larger number of boards with higher average and maximum solution lengths.

<!-- translation -->
我们还发现，与从可解棋盘仅做正向枚举相比，逆向枚举能找到更多棋盘。从已解棋盘开始时，正向方法找不到新棋盘，这并不意外。但即使对于从未解棋盘开始的游戏，逆向枚举仍能找到更多棋盘，而且它们的平均和最大解步长度都更高。

<!-- endpair -->

<!-- pair:en:INV00064:paragraph -->
We also think, subjectively, inverse enumeration finds some interesting levels. For example, the generated Sokoban boards appear to include the provided starting board as a step along the solution path. The generated TwoDoor boards involve backtracking a bit after collecting a key: one to collect the other key behind a door, and one just to use up a key in a door as the player can only exit without a key.

<!-- translation -->
我们还主观地认为，逆向枚举找到了一些有趣关卡。例如，生成的Sokoban棋盘似乎把提供的起始棋盘包含为解题路径中的一步。生成的TwoDoor棋盘则涉及拿到钥匙之后略作折返：一个是去取得门后的另一把钥匙，另一个则只是在门上用掉钥匙，因为玩家只有不携带钥匙时才能退出。

<!-- endpair -->

<!-- pair:en:INV00065:heading -->
## 6. Conclusion

<!-- translation -->
## 6. 结论

<!-- endpair -->

<!-- pair:en:INV00066:paragraph -->
In this work we have presented the concept of program inversion for procedural content generation. Although other work has applied inverted mechanics to content generation in specific games, we show an implementation of that concept using a small version of the Tile Rewrite Rule Behavior Trees domain-specific language that captures a class of simple games. This allows new boards to be generated for these games directly from their source code and a single example board.

<!-- translation -->
本研究提出了将程序反演用于程序化内容生成的概念。虽然已有工作把反演机制用于特定游戏的内容生成，我们展示了这一概念的一种实现：使用图块重写规则行为树这一领域专用语言的小型版本，覆盖一类简单游戏。由此，可以直接依据这些游戏的源代码和单个示例棋盘，为它们生成新棋盘。

<!-- endpair -->

<!-- pair:en:INV00067:paragraph -->
In the future we are interested in expanding the approach to larger, more complex games that use more of the TRRBT language, or other other existing languages such as Ludii or PuzzleScript; also developing approaches to generating levels based just on the game’s code without a provided starting level. By creating a level generator in the same language as the original game, there is the possibility of integrating the two and adding a runtime level generator back into the original game (perhaps as a language feature in a TRRBT transform node). Since the inverted programs are themselves games, it may be possible to play them to generate levels for the original game.

<!-- translation -->
未来，我们希望把这一方法扩展到更大、更复杂的游戏，使其使用更多TRRBT语言功能，或Ludii、PuzzleScript等其他现有语言；也希望发展只依靠游戏代码、不需要给定起始关卡的关卡生成方法。由于关卡生成器使用与原游戏相同的语言，二者有可能整合，把运行时关卡生成器加入原游戏，例如作为TRRBT transform节点中的一种语言功能。由于反演程序本身也是游戏，也许还可以通过游玩这些反演程序，为原游戏生成关卡。

<!-- endpair -->

<!-- pair:en:INV00068:paragraph -->
We would also like to perform a user study of game designers to see how useful this approach is to them. We are also interested in methods to verify inversion works for generating solvable levels theoretically rather than empirically. Finally, program inversion may be useful for generating other types of content.

<!-- translation -->
我们也希望开展面向游戏设计者的用户研究，考察这一方法对他们有多大帮助。此外，我们还对验证反演能够生成可解关卡的理论方法感兴趣，而不只是进行经验验证。最后，程序反演也可能有助于生成其他类型的内容。

<!-- endpair -->
