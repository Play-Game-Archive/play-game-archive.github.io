# 简介

本文将生成关卡任务图的规则与模拟游戏机制的规则放进同一个图文法，再通过约束求解一次生成完整图序列：前半部分创建关卡，后半部分给出抵达目标的通关过程。作者扩展Dormans的冒险游戏任务文法，考察逐规则的边、节点与步骤提示如何限制求解空间，以及节点数量、规则次数和子图匹配等约束如何控制生成结果。案例输出是任务图与机制轨迹；加入机制验证后耗时的显著增长，也是文章报告的主要限制。

## Abstract

<!-- translation -->
## 摘要
<!-- endpair -->

<!-- pair:en:GG0010:abstract-->
Graph grammars are an approach to procedurally generating content for games. However, grammars must often be carefully designed so that generated levels are completable, e.g. keys do not end up behind locks. In this work, we present a graph grammar approach that uses a single unified grammar containing the rules for both generating and playing levels. Such grammars generate not just a level, but an example playthrough of the level. Using a constraint-based application of the grammars can ensure that generated playthrough solves the level. The constraint-based approach is also highly controllable, and can constrain aspects such as the number of times rules are applied, label counts in the generated graph, and matching partial subgraphs. To scale this approach up to larger graphs, we introduce hints into the grammar rules that limit the ranges of variables that can be used for certain nodes and edges. As a motivating example, we reproduce a grammar for generating adventure game missions from Dormans’ previous work, extend it with gameplay rules, and use these for flexible item placement while ensuring completability regarding keys and locks.

<!-- translation -->
图文法是为游戏程序化生成内容的一种方法。不过，通常必须精心设计文法，才能使生成的关卡可以完成，例如避免钥匙最终位于锁后面。在本项工作中，我们提出了一种图文法方法，用一个统一文法同时容纳生成关卡和游玩关卡的规则。这类文法生成的不只是关卡，还包括该关卡的一个通关过程示例。以基于约束的方式应用文法，可以确保生成的通关过程解出关卡。这种基于约束的方法还具有很强的可控性，可以约束规则应用次数、生成图中的标签数量，以及部分子图的匹配等方面。为了将这种方法扩展到更大的图，我们在文法规则中引入提示，限制可用于特定节点和边的变量取值范围。作为动机示例，我们重现了Dormans此前工作中用于生成冒险游戏任务的文法，为其加入玩法规则，并利用这些规则灵活放置物品，同时确保关卡在钥匙与锁方面可以完成。
<!-- endpair -->

## 1. Introduction

<!-- translation -->
## 1. 引言
<!-- endpair -->

<!-- pair:en:GG0014:paragraph-->
Graph grammars are a popular approach to procedural generation of levels for video games [1]. In a graph grammar-based approach, levels are represented as graphs; the grammar provides rules for replacing—or rewriting—certain subgraphs (i.e. arrangements of nodes and edges) with new subgraphs. By repeatedly applying these rules, a graph (and thus level) of the desired complexity can be generated.

<!-- translation -->
图文法是电子游戏关卡程序化生成的一种常见方法[1]。在基于图文法的方法中，关卡被表示为图；文法提供一些规则，用新的子图替换——或重写——特定子图，也就是节点和边的特定排列。通过反复应用这些规则，可以生成具有所需复杂度的图，从而生成相应的关卡。
<!-- endpair -->

<!-- pair:en:GG0015:paragraph-->
As is often the case with level generation, it is critical that levels generated by graph grammars are completable—that is, it is possible for a player to complete the level. This means that, e.g. keys should not be behind their associated locks, special items need to defeat a boss should be collectible before getting to that boss, and so on. A number of techniques have been developed to ensure this, including grammars that prevent such situations [2, 3, 4], generate-and-test [5], and constraint-based approaches [6]. However, these previous approaches require either careful manual design of grammars, or implementing a separate system to check or constrain graphs.

<!-- translation -->
与关卡生成中常见的情况一样，确保图文法生成的关卡可以完成至关重要，也就是说，玩家有可能完成关卡。例如，钥匙不应位于与其对应的锁后面；击败某个首领所需的特殊物品，应能在到达该首领之前取得，等等。为确保这一点，研究者已开发了多种技术，包括能防止这类情况的文法[2, 3, 4]、生成后测试[5]以及基于约束的方法[6]。不过，这些既有方法要么要求精心手工设计文法，要么需要另外实现一个系统来检查图或对图施加约束。
<!-- endpair -->

<!-- pair:en:GG0016:paragraph-->
Recent work has explored representing the game mechanics themselves as rewrites of subgraphs, essentially a graph grammar [7]. By using a constraint-based framework, this grammar representation of the game mechanics could ensure that the generated graphs were completable. The level itself was generated by constraints learned from example graphs [8], and simultaneously, the game mechanic grammar generated a step-by-step playthrough demonstrating how the level could be completed. This was done by creating a sequence of graphs, with each corresponding to an application of a mechanic rule, and ensuring that the level is solved by the last step.

<!-- translation -->
近期的工作探索了将游戏机制本身表示为子图的重写，这实质上也是一种图文法[7]。利用基于约束的框架，这种对游戏机制的文法表示可以确保生成的图可以完成。关卡本身由从示例图中学得的约束生成[8]；与此同时，游戏机制文法会生成一个逐步展开的通关过程，展示关卡如何被完成。实现方式是创建一个图序列，其中每个图对应一次机制规则的应用，并确保关卡在最后一步得到解决。
<!-- endpair -->

<!-- pair:en:GG0017:paragraph-->
In this work, we look at unifying the graph grammar for generating levels and the graph grammar for game mechanics into a single grammar. By unifying these into a single grammar, we can use the previous constraint-based framework to generate graphs that are ensured to be playable in a single constraint problem. We can also use the same representation to describe the rules for generating the graph and ensuring that it is completable.

<!-- translation -->
在本项工作中，我们研究将生成关卡的图文法与游戏机制的图文法统一为一个文法。将两者统一之后，就可以利用既有的约束框架，在一个约束问题中生成保证可玩的图。我们还能够使用同一种表示来描述生成图的规则，并确保图可以完成。
<!-- endpair -->

<!-- pair:en:GG0018:paragraph-->
For motivation, we looked to Dormans’ work on graph grammar generation of adventure game missions [2], recreating it in our system, and augmenting it with mechanic rules. Our constraint-based system allows fine-grained control over generated node labels, rule applications, and even entire subgraphs. While the grammar in Dormans’ work was manually constructed to ensure that keys did not end up behind their locks, our system allows flexibility in key and item placement by the generator rules, while relying on the mechanic rules to ensure completability.

<!-- translation -->
作为研究动机，我们参考了Dormans利用图文法生成冒险游戏任务的工作[2]，在我们的系统中将其重现，并为其增加机制规则。我们的约束系统允许细致控制生成的节点标签、规则应用，甚至整个子图。Dormans工作中的文法经过手工构造，以确保钥匙不会最终落在其对应的锁后面；我们的系统则允许生成规则灵活放置钥匙和物品，同时依靠机制规则确保可完成性。
<!-- endpair -->

<!-- pair:en:GG0019:paragraph-->
At it core, the system we present is an extension to the previous work [7] in which we include both generator rules and mechanic rules, such that some steps in the graph sequence are generating the level and some are of a playthrough ensuring its completability. However, in order to implement Dormans’ grammar, several pragmatic improvements to the system were needed. Perhaps the most important of these was for performance, to scale up to larger graphs with more steps in their generation. We call these grammar hints, which are additional information about the grammar and individual rules to limit their application and thus the constraint problem to be solved. As one example, since the performance of the constraint satisfaction problem is greatly impacted by the number of potential edges in the graph, each grammar rule can have associated with it an edge hint: information about which edges it is allowed to consider based on node IDs; e.g. instead of a rule having to consider any pair of nodes being connected, it may only have to consider situations where the two nodes have relative ids within a certain range, greatly reducing the space of possibilities. Whereas previous work [7] could set such limitations across the entire graph—referred to as edge setup—in this work it can be set per-rule. We have found grammar hints require additional effort to author, but greatly speed up the generation process.

<!-- translation -->
从核心上看，我们提出的系统是既有工作[7]的扩展：它同时包含生成规则和机制规则，使图序列中的一些步骤用于生成关卡，另一些步骤则构成确保可完成性的通关过程。不过，要实现Dormans的文法，还需要对系统做若干实际改进。其中最重要的或许是性能方面的改进，以扩展到更大的图和更多的生成步骤。我们将这些改进称为文法提示，即关于文法及其各条规则的附加信息，用来限制规则的应用，并由此限制需要求解的约束问题。例如，图中潜在边的数量会极大影响约束满足问题的性能，因此每条文法规则都可以附带一个边提示：它依据节点ID，说明该规则可以考虑哪些边。例如，一条规则不必考虑任意两个节点相连的情况，而可能只需考虑两个节点的相对ID处于特定范围内的情况，从而大幅缩小可能性空间。此前的工作[7]只能在整个图的范围内设定这类限制，称为边设置；本项工作则可以逐条规则设定。我们发现，编写文法提示需要额外工作，但会大幅加快生成过程。
<!-- endpair -->

<!-- pair:en:GG0020:paragraph-->
This work contributes a unified graph grammar approach to both generating levels and ensuring their solvability using constraint solving, a demonstration of performance improvements provided by grammar hints, and a demonstration of the controllability of generated graphs afforded by constraint solving.

<!-- translation -->
本项工作的贡献包括：提出一种统一的图文法方法，利用约束求解同时生成关卡并确保其可解；展示文法提示带来的性能改进；展示约束求解为生成图提供的可控性。
<!-- endpair -->

<!-- pair:en:GG0021:heading-->
## 2. Related Work

<!-- translation -->
## 2. 相关工作
<!-- endpair -->

<!-- pair:en:GG0022:paragraph-->
Generating completable levels. To ensure that generated levels are completable, there are multiple approaches that are commonly used. One common method is agent-based testing, in which completability is assured by agents attempting to play the levels [9]. Another approach is to add constraints during generation, so that levels always meet some requirements. For example, Nelson and Smith [10] used answer set programming to encode rules about valid paths or item placement. Other systems like Sturgeon combine the rules specified by the designer and learned pattern constraints to guarantee reachability [6]. On the other hand, generate-and-repair techniques have a different approach, in which they ensure completability after the generation process is complete. Autoencoders have been used to automatically fix uncompletable structures by reconstructing levels [11]. More recent methods use explainable AI to detect problematic regions and guide targeted repairs to minimally edit levels until completability is achieved [12].

<!-- translation -->
生成可完成的关卡。为确保生成的关卡可以完成，研究中常用多种方法。一种常见方法是基于智能体的测试，通过让智能体尝试游玩关卡来保证可完成性[9]。另一种方法是在生成过程中加入约束，使关卡始终满足某些要求。例如，Nelson和Smith[10]使用答案集编程，对有效路径或物品放置的规则进行编码。Sturgeon等其他系统则结合设计者指定的规则与学得的模式约束，以保证可达性[6]。另一方面，生成后修复技术采用不同的方法，在生成过程完成后确保可完成性。已有研究用自编码器重构关卡，自动修复不可完成的结构[11]。较新的方法使用可解释AI检测存在问题的区域，并引导针对性修复，以尽可能少地修改关卡，直至实现可完成性[12]。
<!-- endpair -->

<!-- pair:en:GG0023:paragraph-->
Generating levels with graph grammars. Graph grammars have been widely explored for level generation. The early work of Adams [13] was one of the earliest works that used a graph grammar (instead of phrase structure grammars) to generate FPS-style dungeons to utilize the power of graphs to represent the complex patterns of connectivity that are found in levels. Following this work, Dormans [2] viewed level design as a sequence of model transformations, and created mission grammars (that included players’ missions and tasks) that get mapped to space graphs (that included spatial layout of levels). Font et al. [4] created a two-stage evolutionary method in which a high-level graph of areas is first evolved, and then expanded into detailed room graphs. They created examples of lock-and-key puzzles that were guaranteed to be completable. Londoño and Missura [14] introduced stochastic graph grammars to learn structural properties from Super Mario Bros levels and generate new levels with similar qualities to expert design. Later review works on graph grammars highlighted that grammars naturally capture high-level structural design patterns [15] and explored expansive examples of level structures and quest generation [16]. Other work has looked at using graph grammars to generate puzzles in educational games [17]. The sophisticated LudoScope level generation system [18, 19] allows a great degree of control over levels generated by graph grammars, for example recipes that can specify the number of times to apply a rule.

<!-- translation -->
用图文法生成关卡。图文法已广泛用于关卡生成。Adams的早期工作[13]是最早使用图文法、而非短语结构文法，来生成FPS风格地下城的工作之一，借助图来表示关卡中复杂的连接模式。随后，Dormans[2]将关卡设计视为一系列模型变换，并创建任务文法，其中包含玩家的任务与目标；这些文法会映射为空间图，后者包含关卡的空间布局。Font等人[4]创建了一种两阶段演化方法，先演化由区域构成的高层图，再将其扩展为详细的房间图。他们生成了保证可以完成的锁与钥匙谜题示例。Londoño和Missura[14]引入随机图文法，从《Super Mario Bros》的关卡中学习结构属性，并生成具有类似专家设计品质的新关卡。后来的图文法综述指出，文法能够自然地捕捉高层结构设计模式[15]，并广泛考察了关卡结构与任务生成的示例[16]。其他工作还研究了用图文法生成教育游戏中的谜题[17]。复杂的LudoScope关卡生成系统[18, 19]允许对图文法生成的关卡进行高度控制，例如用生成配方指定一条规则的应用次数。
<!-- endpair -->

<!-- pair:en:GG0026:heading-->
## 3. System Overview

<!-- translation -->
## 3. 系统概述
<!-- endpair -->

<!-- pair:en:GG0027:paragraph-->
For the most part, the core graph grammar system used in this work is similar to that presented in previous work [7], except that some rules conceptually represent graph generation and some represent gameplay mechanics. We briefly describe the previous system, in which rules represented only gameplay mechanics, and were used to ensure that a generated graph could be completed by those mechanics by generating a playthrough. The rules could rewrite the labels on subgraphs: at each step, a subgraph matching the labels on the left-hand side of the rules could be rewritten as the labels on the right-hand side; each node and edge has a static label, which cannot change from step to step, and a dynamic label, which can change from step to step. Visually, each rule is represented as a graph with the left- and right-hand side labels on each node and edge. These rules are incorporated into a constraint satisfaction problem that creates a sequence of graphs, each representing a step in the solution. Roughly speaking, the constraint problem is set up with a (Boolean) variable for each possible label for each possible node and edge, and for dynamic labels, these are for every step. The graphs in the sequence are constrained such that the labels can only change according to the mechanic rules, and the final graph is constrained to be solved; thus, the created sequence of graphs show how the initial graph can be solved by the mechanics as a playthrough. The problem setup must also be provided with a maximum graph size (in terms of nodes) and maximum number of steps, although steps can be marked as terminal, after which no more changes are made.

<!-- translation -->
本项工作所用图文法系统的核心，大体上与既有工作[7]提出的系统相似，区别在于，一些规则在概念上表示图的生成，另一些规则表示玩法机制。下面简述既有系统：其中的规则只表示玩法机制，并通过生成通关过程来确保生成的图可由这些机制完成。规则可以重写子图上的标签：在每一步中，匹配规则左侧标签的子图，都可以被重写为右侧标签。每个节点和每条边都有一个静态标签，不能随步骤变化；还有一个动态标签，可以随步骤变化。在视觉表示上，每条规则是一幅图，其各节点和边同时带有左侧与右侧标签。这些规则被纳入一个约束满足问题，创建图序列，其中每幅图表示求解过程中的一步。大致而言，约束问题为每个可能节点、每条可能边的每种可能标签建立一个布尔变量；对动态标签而言，每一步都要建立这些变量。图序列受到约束，标签只能依照机制规则变化，最终图则必须处于已解决状态。因此，创建出的图序列作为通关过程，展示初始图如何由这些机制解出。问题设置还必须给出图的最大规模，以节点数量计，以及最大步骤数；不过，某些步骤可以标记为终止步骤，此后不再进行任何修改。
<!-- endpair -->

<!-- pair:en:GG0028:paragraph-->
As the constraint problem is essentially solving for a label for each node and edge in each timestep, practical considerations about the number of edges that need to be considered can impact performance, as this number grows rapidly as the number of nodes increases. Previously, the number of edges was reduced by an approach called the edge setup. Each node has an ID, from 1...𝑁 , where 𝑁 is the maximum number of nodes in the generated graph. The edge setup globally limited which pairs of nodes could potentially have an edge between them based on ID. Though this is configurable, a straightforward edge setup simply only allows edges from a node ID 𝑖 to nodes up to ID 𝑖 + 𝑛.

<!-- translation -->
由于约束问题实质上是在每个时间步为各节点和边求解标签，需要考虑的边的数量会影响实际性能；随着节点增多，这一数量会迅速增长。此前采用一种称为边设置的方法来减少边数。每个节点都有一个从1...𝑁取值的ID，其中𝑁是生成图的最大节点数。边设置依据ID，在全图范围限制哪些节点对之间可能有边。虽然这一设置可以配置，一种直接的方法是，只允许从ID为𝑖的节点连到ID不超过𝑖+𝑛的节点。
<!-- endpair -->

<!-- pair:en:GG0029:paragraph-->
Here now we describe some of the most salient changes from the previous system, updated for this work. As an illustration, we refer to Figure 1, which shows a small set of generator rules and a resulting graph sequence generated by them. In this simple example, the steps only generate a graph in the final step and do not create a playthrough (we use the term graph sequence in general as the steps may be part of generating the graph or part of the playthrough). On the right, there are two generator rules: one that replaces the S node with two others, and then another rule that replaces those two with several other nodes. Constraints are added such that final graph must not have any S, X1 or X2 nodes. On the left the resulting generated graph sequence is shown. Note that the output of the solver is not just the graph from the last step, but the entire sequence of graphs at once.

<!-- translation -->
现在介绍相对于既有系统、本项工作更新的一些主要改动。以图1为例，图中展示了一小组生成规则，以及它们生成的图序列。在这个简单例子中，各步骤只在最后一步生成一幅图，不创建通关过程；我们一般使用“图序列”一词，因为其中的步骤既可能属于图的生成，也可能属于通关过程。右侧有两条生成规则：第一条将S节点替换为另外两个节点，第二条再将这两个节点替换为若干其他节点。我们加入约束，使最终图不得包含任何S、X1或X2节点。左侧展示了生成的图序列。请注意，求解器一次输出的不只是最后一步的图，而是整个图序列。
<!-- endpair -->

<!-- pair:en:GG0030:list_item-->
• Labels. In this work we introduced two special labels: the nil label NIL (shown in figures as ∙), which means that a node or edge is not present, and the start label, S, which represents the start node. To use the existing system, which learned from example training graphs to create the initial graph (the graph in step 0), an example training graph is supplied with a single S node connected to a single NIL node by a NIL edge. The initial graph is constrained to have a single S node, with the rest of the nodes and all edges labeled NIL. Only dynamic labels, that can change from step to step, are used—static labels, though present from the previous system, are set to a fixed value and ignored. So, for example, the first rule in the top-left of Figure 1 can rewrite a S node, along with a non-present NIL edge to a non-present NIL node (the left-hand side of the rule), with a node labeled X1 to a node labeled X2 by and edge labeled labeled _ (the right-hand side of the rule). This happens in the generated graph sequence in step 2.

<!-- translation -->
• 标签。本项工作引入两个特殊标签：空标签NIL（图中以∙表示），意为某个节点或边不存在；以及起始标签S，表示起始节点。既有系统通过从示例训练图中学习来创建初始图，也就是步骤0的图。为使用该系统，我们提供了一幅示例训练图：一个S节点通过一条NIL边连接一个NIL节点。初始图受到约束，只能有一个S节点，其余节点和全部边都标为NIL。系统仅使用可随步骤变化的动态标签；既有系统中的静态标签仍然存在，但被设为固定值并忽略。例如，图1左上方第一条规则可以将一个S节点，以及一条通向不存在的NIL节点、同样不存在的NIL边（规则左侧），重写成一个标为X1的节点，通过一条标为_的边连接一个标为X2的节点（规则右侧）。这发生在生成图序列的步骤2。
<!-- endpair -->

<!-- pair:en:GG0031:list_item-->
• Edge hints. Edge hints can be used to specify on a per-rule basis information about which node IDs should be considered for an edge to connect. These can be relative, meaning they are deltas to the source node ID (shown in figures as +𝑛), or absolute, meaning only a specific node ID can be considered (shown in figures as @𝑛). For example, in the first rule in the top-left of Figure 1, the +7 . . . + 9 means that ID of the node rewritten to X2 must be 7 to 9 greater than the node ID rewritten to X1. This can be used to greatly limit the number of edges in consideration for this rule.

<!-- translation -->
• 边提示。边提示可以逐条规则指定哪些节点ID应当被考虑为边的连接对象。它可以是相对的，表示相对于源节点ID的增量（图中写作+𝑛）；也可以是绝对的，表示只考虑特定节点ID（图中写作@𝑛）。例如，图1左上方第一条规则中的+7…+9表示，被重写为X2的节点，其ID必须比被重写为X1的节点ID大7至9。这可以大幅限制该规则需要考虑的边的数量。
<!-- endpair -->

<!-- pair:en:GG0032:list_item-->
• Node hints. Node hints can be used to specify on which node IDs and in which steps node labels can be present.

<!-- translation -->
• 节点提示。节点提示可用于指定节点标签能够出现在哪些节点ID上，以及哪些步骤中。
<!-- endpair -->

<!-- pair:en:GG0033:list_item-->
• Rule hints. Rule hints can be used to specify in which steps a rule can be applied.

<!-- translation -->
• 规则提示。规则提示可用于指定规则能够在哪些步骤应用。
<!-- endpair -->

<!-- pair:en:GG0034:list_item-->
• Skipped rule application. Whereas in the previous system one rule had to apply each step (until the terminal step), a specific step can allow no rules to be applied.

<!-- translation -->
• 跳过规则应用。既有系统要求每一步都应用一条规则，直到终止步骤；现在可以允许某个特定步骤不应用任何规则。
<!-- endpair -->

<!-- pair:en:GG0035:list_item-->
• Simultaneous rule application. Multiple rules can be allowed to be applied in the same step, as long as they do not involve any of the same nodes or edges. This can allow the number of steps to be reduced, making the problem size smaller.

<!-- translation -->
• 同时应用规则。可以允许多条规则在同一步应用，前提是它们不涉及任何相同的节点或边。这可以减少步骤数，从而缩小问题规模。
<!-- endpair -->

<!-- pair:en:GG0036:list_item-->
• Required rule application. In conjunction with skipped and simultaneous rule application, a step can require all rules that can be applied to be applied.

<!-- translation -->
• 必需的规则应用。结合跳过和同时应用规则的能力，可以要求某一步中所有能够应用的规则都必须被应用。
<!-- endpair -->

## 5. Generating Missions

<!-- translation -->
## 5. 生成任务
<!-- endpair -->

<!-- pair:en:GG0043:paragraph-->
As our motivating example, we sought to recreate Dormans’ [2] adventure game mission grammar in our constraint-based system, and augment it with mechanic rules. As it it quite large, we start with a simplified version, referred to as mini-Dormans, to explain how the new features of the system were used to implement it.

<!-- translation -->
作为动机示例，我们尝试在基于约束的系统中重现Dormans[2]的冒险游戏任务文法，并为其增添机制规则。由于该文法相当庞大，我们先从一个称为mini-Dormans的简化版本入手，说明如何运用系统的新特性来实现它。
<!-- endpair -->

<!-- pair:en:GG0044:paragraph-->
The grammar is shown in Figure 2. Edge hints are used throughout; rule hints are used to limit the steps in which rules can apply. Node hints are used to make sure all non-terminal labels are gone by the step the generate rules are done applying. Node hints are used, in conjunction with edge hints to implement an inventory system. Simultaneous rule application is allowed, and skipped/required rule application is used to force the application of rules related to edge traversability. By the end of the graph sequence, the goal node label must be gone (due to the player moving onto it).

<!-- translation -->
文法见图2。整个文法都使用边提示；规则提示用于限制规则可应用的步骤。节点提示用于确保生成规则应用完毕时，全部非终结标签都已消失。节点提示还与边提示结合，用来实现物品栏系统。系统允许同时应用规则，并利用跳过／必需规则应用，强制执行与边的可通行性有关的规则。在图序列结束时，目标节点的标签必须消失，因为玩家已移动到该节点上。
<!-- endpair -->

<!-- pair:en:GG0045:paragraph-->
The first generate rule creates two corridors C each followed by a lock l; it can only be used between steps 0 and 1. The next two generate rules can replace these corridors C with slots SL in sequence or parallel, and the next two replace a slot SL with either a key k or nothing n; these can only apply between steps 1 and 3. At this point in the steps the level has been generated. The next rules are meant as a proxy for spatial information in Dormans’ grammar to set up for the mechanic rules: in the original grammar, double edges indicate part of the mission should be spatially behind another when turned into a space. Since we are not generating the space, we instead make all the other edges leading to a node that should be behind a node not travesible. This is accomplished by a required rule application rewriting all incoming single dash - edges to a node with an incoming equal = edge to be an untraversible x between steps 3 and 4, and then marking all the remaining edges as a traversible period . between steps 4 and 5 (the box □ in a node means it that node is ignored in the rule). At this point the playthrough begins: the next rule sets up the player @, with an inventory, which uses node hints and edge hints to use the label at node ID 0 (k:_, k:1, k:2) to count the number of keys k the player has collected. The remaining mechanic rules allow the player to move through the graph, collecting keys and using them to open locks, and reach the goal.

<!-- translation -->
第一条生成规则创建两段走廊C，每段后面各有一把锁l；它只可在步骤0与1之间使用。接下来的两条生成规则可用串联或并联的槽位SL替换走廊C，再接下来的两条则将槽位SL替换为钥匙k或空置n；它们只可在步骤1与3之间应用。进行到此，关卡已经生成。接下来的规则代替Dormans文法中的空间信息，为机制规则作准备：在原文法中，双边表示任务的某一部分在转化为空间后，应位于另一部分之后。由于我们不生成空间，因此改为将所有其他通向那个应位于某节点之后的节点的边设为不可通行。具体而言，在步骤3与4之间，利用必需规则应用，将所有进入某节点的单横线-边重写为不可通行的x，条件是该节点另有一条进入它的等号=边；然后在步骤4与5之间，将所有剩余边标为可通行的点号.。节点内的方框□表示该节点在规则中被忽略。此时通关过程开始：下一条规则建立带有物品栏的玩家@；它利用节点提示与边提示，在节点ID 0上使用标签k:_、k:1、k:2，记录玩家已收集的钥匙k的数量。余下的机制规则允许玩家在图中移动、收集钥匙并用其开锁，最终抵达目标。
<!-- endpair -->

<!-- pair:en:GG0046:paragraph-->
Top control the generated level, constraints are added so that sequence and parallel corridor rules are used once each, and step 3 has 2 keys. The maximum size is 15 nodes and maximum steps is 20. The same solver setup is used as above, and 25 graph sequences were generated.

<!-- translation -->
为控制生成的关卡，我们加入约束：串联走廊规则和并联走廊规则各使用一次，且步骤3中有2把钥匙。最大规模为15个节点，最大步骤数为20。我们使用与上述相同的求解器配置，生成25个图序列。

The next three steps create the graph structure and place the keys. Step 6 begins the application of the mechanic rules, with the player appearing with an empty inventory. <!-- pair:en:GG0063:heading-->
## 6. Conclusion

<!-- translation -->
## 6. 结论
<!-- endpair -->

<!-- pair:en:GG0064:paragraph-->
In this work we have presented an approach to generate completable levels using graph grammars. The approach combines rules for generating graphs with rules for running game mechanics on graphs into a single unified grammar. Using a constraint-based system that generates a graph sequence, where the grammar constrains changes between graphs in the sequence and the level must be solved by the final step, the mechanic rule ensure that the level generated by the generate rules can be completed. We describe some practical improvements over the previous system and show their beneficial impact on timing. We also recreate and augment the adventure game mission grammar of Dormans and show how the constraint-based approach can provide controllability of generated graphs.

<!-- translation -->
本项工作提出了一种使用图文法生成可完成关卡的方法。该方法将生成图的规则与在图上运行游戏机制的规则结合为一个统一文法。系统基于约束，生成图序列：文法约束序列中图与图之间的变化，并要求关卡在最后一步得到解决；由此，机制规则确保生成规则创建的关卡可以完成。我们描述了对既有系统的若干实际改进，并展示其对耗时的有利影响。我们还重现并扩展了Dormans的冒险游戏任务文法，展示基于约束的方法如何控制生成的图。
