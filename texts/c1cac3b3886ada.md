# 简介

SimCity是Will Wright设计、Maxis于1989年推出的城市模拟游戏。玩家划定住宅、商业与工业用地，建设道路、电力和公共设施，安排税收与维护费用，再观察城市如何发展、衰退或遭遇灾难。玩家没有直接指挥每一位居民，而是改变他们生活与生产的条件，让城市通过一组相互联系的规则回应规划。

这里的对象是1989年初作及其早期电脑移植，不与SimCity 2000、2013年同名作品或Super Nintendo改编版混用。原作已有不同平台的界面与内容差别。早期Infogrames的Amstrad与Spectrum手册明确列出移植人员；本文借其说明共同的城市机制，不把它的键位、画面和全部细节当作Macintosh首发版的记录。[1]

# 把建设交给玩家，把生长交给模型

SimCity把城市分为居住、商业和工业三个主要用途。玩家首先提供地块、供电和交通条件，居民与企业再依模型决定是否进入、建造和继续发展。规划者的行为与城市的生长之间留有时间差，按下建设按钮不会立刻产生一座繁荣城区。[1]

这种间接关系改变了策略的重心。玩家需要判断空置是缺电、道路不通、就业不足，还是污染和税率让地区失去吸引力。一次措施可能修补局部问题，也可能让另一个指标恶化。城市不是等待玩家完成的固定图案，而是会持续评价自己所处条件的系统。

住宅提供劳动力，工业面向外部市场，商业服务内部需求。手册把这些联系解释为不同的增长动力：小城的商业需求可能有限，人口增加以后，内部市场又会推动更多发展。玩家需要理解区域比例与需求变化，而不只是把三种颜色平均涂满地图。

Wright从1985年开始开发这项构想，后来与Jeff Braun共同创办Maxis。作品在1989年进入公众市场。这个时间过程说明，常被概括为一个灵感的城市玩具，实际上需要数年的模型、界面与发行准备。设计者的个人贡献和工作室的生产条件应当同时保留。[2]

# 基础设施把空间连接成城市

供电是地区发展的必要条件。电厂、线路和已经连接的区域共同形成网络，灾难或拆除可能切断它。供电状态由系统计算，并通过相应反馈呈现；玩家必须查看连接关系，而不能只欣赏城市外观。[1]

道路和铁路也具有持续成本。修建时支付费用，随后仍要维护；经费不足会使交通设施退化。扩张因此不仅需要一次性资金，还会产生未来责任。远处的新区域可能增加税源，也可能让尚未成熟的财政承担过长的线路与道路。

早期手册用“行程生成”解释交通：区域产生出行，沿交通网络寻找适当目的地，失败会限制发展。这里不需要假定每个屏幕小点都代表一个拥有完整人生的市民。交通可以通过抽象过程影响区域状态，画面中的车辆只是模型反馈的一部分。[1]

交通容量、通达性与污染又联系起来。多修道路可能改善连接，也会占用土地、增加维护和交通相关污染。铁路提供另一种选择，却具有不同成本。玩家面对的并非“交通越多越好”的简单公式，而是网络、财政和居住质量之间的组合问题。

电网冗余同样体现了取舍。额外线路可能在局部损坏后维持供电，也要支付建设成本。灾难发生前看似浪费的投入，可能在危机时显现价值。模拟通过时间把成本与收益拉开，使基础设施的意义不能只用眼前账面余额衡量。

# 税率与公共服务的反馈

税收把增长转化为能够继续建设的资金。税率过低可能吸引发展，却让公共维护缺钱；过高可能短期增加收入，随后促使居民和企业离开。手册明确把税率看作会影响整个城市发展速度的变量。这个规则是作品的模型假设，不是关于现实财政的一条普遍经济定律。[1]

警察、消防与交通部门分别需要经费。建一座警局与保证它有效工作，是两项不同决定；经费会影响服务范围与效果。玩家因此可能拥有设施，却仍无法得到预期保护。城市图像与预算窗口共同说明系统状态，任何一面都不足以替代另一面。

警局在模型中降低范围内犯罪，消防局影响火灾的预防与扑灭，交通维护决定道路能否继续使用。玩家需要把服务覆盖放回实际空间，看人口和设施是否分布合理。公共预算不是抽象数字游戏，它会改变某个地区的风险与吸引力。

这种结构也让衰退可能自我加强。地区条件恶化会减少人口或发展，税源下降又限制维护，进一步削弱环境。玩家不能只等城市自然恢复，而需要在财政紧张时找到能打断反馈的措施。相反，良好服务和增长之间也可能形成正向循环，但前提是新增收入足以承担随之增加的成本。

# 地价、污染与规划的价值判断

地价把多种环境条件压缩成可比较的指标。靠近水域、绿地与服务的区域更有吸引力，污染和犯罪则降低发展条件。玩家通过地图查看这些分布，把局部景观转化为整个城市的判断依据。地价由此既是经济变量，也是界面组织空间价值的方式。[1]

工业提供工作和收入，也制造不受欢迎的环境影响。把它远离住宅可以减少干扰，却需要保证通勤和运输仍然有效。作品并没有让任何区域完全脱离其他区域而独立成功。它把规划表现为处理互相需要、又互相妨碍的用途。

手册还把人口密度、低地价与犯罪联系起来，并提出通过警力或改造区域改善状况。这样的规则可以被分析，也应当被质疑。现实犯罪具有历史、制度与社会关系等复杂原因，把它浓缩成几个指标会遮蔽许多经验。游戏中的有效方案不能自动成为现实治理的正当理由。

拆除和重新分区在游戏里是直接可用的工具，其社会代价却没有得到与资金相同密度的模拟。居住者的迁移、社区关系和对规划的抗议，并不构成同等可操作的阻力。这个不对称赋予玩家很强的规划权，也使作品的城市观带有明确位置：城市主要作为可以从上方调节的系统出现。

因此，SimCity的教育价值不只在于教人掌握指标。更深入的阅读还包括问哪些关系被选进模型，哪些后果被略去，以及谁有权决定什么算“好城市”。规则越清楚，越适合被拿来比较和讨论；清楚不等于中立，简化也不是没有立场。

# 灾难让维护成为可见事件

火灾、洪水、地震等事件可以打断常规发展。它们让平时不显眼的电网、服务范围和空间安排接受检验。没有准备的城区可能迅速连锁受损；拥有替代连接的地方则可能保留更多恢复条件。灾难把规划的长期后果集中成一个可见时刻。[1]

玩家还能够主动触发灾难。原本作为市长建设城市的人，转而成为试验环境承受能力的操作者。这个权限与普通行政身份并不一致，却符合软件玩具的形式：玩家可以建立、破坏、重载，再观察同一系统的不同过程。

火灾蔓延与道路、树林、空地之间的关系，使拆出隔离带具有局部策略意义；洪水又使岸线附近设施面临不同风险。灾难并非只替换一张受损图片，它改变具体地块和连接，需要人重新安排资源。恢复不是自动回到先前状态，而是另一轮建设决定。

灾难也带来关于现实感的分歧。它可以强调城市脆弱性，促使玩家考虑冗余；主动召唤灾难又可能把市民痛苦变成观赏性的破坏。作品允许两种态度在同一工具中存在。分析这种愉悦，不需要先替每位玩家判断动机，而可以考察界面怎样给予距离、控制与可逆性。

# 图层、窗口与系统学习

俯视地图提供整体轮廓，专门图层显示人口、交通、污染或公共服务等信息。玩家不断切换观察方式，才有可能解释同一地区为什么发展。界面没有把“真实城市”作为一幅最终图像交付，而是把多种互相不完全重叠的描述并列出来。

预算、评价和提示信息进一步为变化提供解释。居民不满税率、部门经费不足或运输退化，会以文字或指标出现。玩家可以据此提出假设，再修改规划并观察后果。反馈不必完全透明才会引发学习，但若没有任何可追踪提示，试验就容易退化为盲目堆设施。

时间速度与暂停使规划和观察能够交替进行。玩家可以暂时放慢过程，检查网络或安排工具，再让城市运行看结果。这种控制把真实城市中难以压缩的等待转化为可操作的实验节奏。它也是作品成为娱乐模拟而非单纯专业计算工具的重要条件。

手册建议在试行政策之前另存城市，比较不同发展路径。存档在这里不只挽救失败，也支持一种分叉实验：保持同一初始条件，尝试不同分区或预算。这个能力增强了观察，却也使玩家拥有现实治理者难以获得的撤销权；游戏经验因此带有鲜明的媒介条件。[1]

相同的人口数字也可能来自不同城市结构。一个地方道路密集、扩张迅速，另一个依靠更紧凑的布局维持收支，两者不应只因总人口相近就被看成同一成果。观察图层与长期变化，使玩家能够把一个抽象成绩重新分解为空间和制度选择。这样的比较既能在游戏内指导下一步，也能训练人注意模型把什么压缩成了同一个指标。

城市还会把政策效果延后显现。修建新区域时的支出很明确，未来税源和维护负担却需要等待。玩家必须在结果尚未完全出现时继续决定，因而经验既来自确切反馈，也来自对延迟的耐心。因此，规划像一次试探，初期增长之后仍需观察税收能否长期负担维护开支。

# 开放目标与情节式挑战

自由建设没有一条必须达到的唯一结局。玩家可以追求人口规模，也可以经营较小、财政稳定、环境舒适的城市。手册甚至明确说明，更大不自动等于更好。作品允许人们把不同理想带进同一规则框架，再通过运行观察它们是否能够自持。[1]

与此同时，原作也包含有指定状况和目标的场景。它们把玩家放进已有城市的问题中，要求在特定期限和条件下应对危机。自由建设与场景挑战并存，所以用“完全没有目标”概括SimCity并不准确。目标既可能由程序给定，也可能由玩家自行提出。

这种形式使故事主要来自过程。一次扩张、一次电力中断或一场财政危机，可以成为玩家记住的城市史；屏幕上没有必要出现一个始终固定的主角。城市本身具有时间连续性，玩家通过建设与补救承担其中的行动角色。

然而，故事仍依赖模型选择。把污染移到城市一边、用较高地价推动发展，能够形成一种成功叙述；未被模拟的迁移者与社会冲突则很难以同样方式进入成绩。玩家创造自己的城市，也在作者规定的可见指标中理解“自己的成功”。

# 玩具形式中的审美

城市外观由玩家的布局和模型的发展共同生成。规整街区、弯曲岸线、工业边缘与高密度中心，既表达规划选择，也记录随后发生的增长。玩家能够为形状感到满意，即使它尚未取得最高人口；也可能为了财政效率牺牲原先喜欢的轮廓。功能与形式的协商因此进入持续游玩。

地形让这种协商拥有起点。水域、树林和可建设面积构成约束，玩家不能只在完全相同的空白纸上画图。保留一片绿地，既可能是审美偏好，也会与地价、扩张成本和交通路线发生联系。环境没有被简单分成纯装饰和纯功能，两者在同一格地图上重叠。

观看城市自行生长也提供了不同于直接操纵的乐趣。玩家设置条件以后暂时退后，观察空地变成建筑、规模扩大或地区衰落，再决定是否干预。行动与旁观互相交替，使作品既像经营挑战，也像一件能够运转的动态模型。城市的可亲近感来自这种被创造又不完全受控的变化。

这种审美不能用真实建筑照片的标准衡量。小图块省略了生活细节，却让全局关系容易被读出；统计图层又使不可见过程获得空间形态。地图、数字和生长动画共同构成作品的表现语言，而不是等到规划结束以后才补上一层装饰。

# 版本、开放代码与影响边界

不同早期电脑平台需要重新安排菜单、键位、颜色与显示密度。Infogrames手册列出的A. R. Lill程序、J. Lawson图形等分工，属于特定移植工作，不能用来取代Wright的原作设计，也不应被系列品牌遮蔽。移植者参与了作品如何被具体使用的创作。[1]

后来以Micropolis名义开放的Unix版本，为研究城市规则提供了另一组材料。Don Hopkins的发布页明确说明其代码来自约1990年的Unix版本，并为OLPC计划修改；代码许可也保留了对SimCity商标的限制。这份代码保存了原作在后续整理与开放过程中的实现。[3]

开放代码呈现了区域、交通与灾难等过程的计算方式。后来整理的算法与1989年版本之间，存在具体的继承和修改关系；不同平台也会围绕类似工具采用各自的实现。

SimCity的持续意义，在于它把模型当成创作媒介。玩家改变条件，系统产生反馈，人再根据反馈修订自己的城市理想。它既支持设计、观察和叙事，也把规划权、指标政治和模拟边界交给批评。理解这些具体关系，比把它只称作无限自由的造城游戏更能解释作品为何重要。

# 基础设施把空间连接成城市

供电是地区发展的必要条件。电厂、线路和已经连接的区域共同形成网络，灾难或拆除可能切断它。供电状态由系统计算，并通过相应反馈呈现；玩家必须查看连接关系，而不能只欣赏城市外观。[1]

道路和铁路也具有持续成本。修建时支付费用，随后仍要维护；经费不足会使交通设施退化。扩张因此不仅需要一次性资金，还会产生未来责任。远处的新区域可能增加税源，也可能让尚未成熟的财政承担过长的线路与道路。

早期手册用“行程生成”解释交通：区域产生出行，沿交通网络寻找适当目的地，失败会限制发展。这里不需要假定每个屏幕小点都代表一个拥有完整人生的市民。交通可以通过抽象过程影响区域状态，画面中的车辆只是模型反馈的一部分。[1]

交通容量、通达性与污染又联系起来。多修道路可能改善连接，也会占用土地、增加维护和交通相关污染。铁路提供另一种选择，却具有不同成本。玩家面对的并非“交通越多越好”的简单公式，而是网络、财政和居住质量之间的组合问题。

电网冗余同样体现了取舍。额外线路可能在局部损坏后维持供电，也要支付建设成本。灾难发生前看似浪费的投入，可能在危机时显现价值。模拟通过时间把成本与收益拉开，使基础设施的意义不能只用眼前账面余额衡量。

# 税率与公共服务的反馈

税收把增长转化为能够继续建设的资金。税率过低可能吸引发展，却让公共维护缺钱；过高可能短期增加收入，随后促使居民和企业离开。手册明确把税率看作会影响整个城市发展速度的变量。这个规则是作品的模型假设，不是关于现实财政的一条普遍经济定律。[1]

警察、消防与交通部门分别需要经费。建一座警局与保证它有效工作，是两项不同决定；经费会影响服务范围与效果。玩家因此可能拥有设施，却仍无法得到预期保护。城市图像与预算窗口共同说明系统状态，任何一面都不足以替代另一面。

警局在模型中降低范围内犯罪，消防局影响火灾的预防与扑灭，交通维护决定道路能否继续使用。玩家需要把服务覆盖放回实际空间，看人口和设施是否分布合理。公共预算不是抽象数字游戏，它会改变某个地区的风险与吸引力。

这种结构也让衰退可能自我加强。地区条件恶化会减少人口或发展，税源下降又限制维护，进一步削弱环境。玩家不能只等城市自然恢复，而需要在财政紧张时找到能打断反馈的措施。相反，良好服务和增长之间也可能形成正向循环，但前提是新增收入足以承担随之增加的成本。

# 地价、污染与规划的价值判断

地价把多种环境条件压缩成可比较的指标。靠近水域、绿地与服务的区域更有吸引力，污染和犯罪则降低发展条件。玩家通过地图查看这些分布，把局部景观转化为整个城市的判断依据。地价由此既是经济变量，也是界面组织空间价值的方式。[1]

工业提供工作和收入，也制造不受欢迎的环境影响。把它远离住宅可以减少干扰，却需要保证通勤和运输仍然有效。作品并没有让任何区域完全脱离其他区域而独立成功。它把规划表现为处理互相需要、又互相妨碍的用途。

手册还把人口密度、低地价与犯罪联系起来，并提出通过警力或改造区域改善状况。这样的规则可以被分析，也应当被质疑。现实犯罪具有历史、制度与社会关系等复杂原因，把它浓缩成几个指标会遮蔽许多经验。游戏中的有效方案不能自动成为现实治理的正当理由。

拆除和重新分区在游戏里是直接可用的工具，其社会代价却没有得到与资金相同密度的模拟。居住者的迁移、社区关系和对规划的抗议，并不构成同等可操作的阻力。这个不对称赋予玩家很强的规划权，也使作品的城市观带有明确位置：城市主要作为可以从上方调节的系统出现。

因此，SimCity的教育价值不只在于教人掌握指标。更深入的阅读还包括问哪些关系被选进模型，哪些后果被略去，以及谁有权决定什么算“好城市”。规则越清楚，越适合被拿来比较和讨论；清楚不等于中立，简化也不是没有立场。

# 灾难让维护成为可见事件

火灾、洪水、地震等事件可以打断常规发展。它们让平时不显眼的电网、服务范围和空间安排接受检验。没有准备的城区可能迅速连锁受损；拥有替代连接的地方则可能保留更多恢复条件。灾难把规划的长期后果集中成一个可见时刻。[1]

玩家还能够主动触发灾难。原本作为市长建设城市的人，转而成为试验环境承受能力的操作者。这个权限与普通行政身份并不一致，却符合软件玩具的形式：玩家可以建立、破坏、重载，再观察同一系统的不同过程。

火灾蔓延与道路、树林、空地之间的关系，使拆出隔离带具有局部策略意义；洪水又使岸线附近设施面临不同风险。灾难并非只替换一张受损图片，它改变具体地块和连接，需要人重新安排资源。恢复不是自动回到先前状态，而是另一轮建设决定。

灾难也带来关于现实感的分歧。它可以强调城市脆弱性，促使玩家考虑冗余；主动召唤灾难又可能把市民痛苦变成观赏性的破坏。作品允许两种态度在同一工具中存在。分析这种愉悦，不需要先替每位玩家判断动机，而可以考察界面怎样给予距离、控制与可逆性。

# 图层、窗口与系统学习

俯视地图提供整体轮廓，专门图层显示人口、交通、污染或公共服务等信息。玩家不断切换观察方式，才有可能解释同一地区为什么发展。界面没有把“真实城市”作为一幅最终图像交付，而是把多种互相不完全重叠的描述并列出来。

预算、评价和提示信息进一步为变化提供解释。居民不满税率、部门经费不足或运输退化，会以文字或指标出现。玩家可以据此提出假设，再修改规划并观察后果。反馈不必完全透明才会引发学习，但若没有任何可追踪提示，试验就容易退化为盲目堆设施。

时间速度与暂停使规划和观察能够交替进行。玩家可以暂时放慢过程，检查网络或安排工具，再让城市运行看结果。这种控制把真实城市中难以压缩的等待转化为可操作的实验节奏。它也是作品成为娱乐模拟而非单纯专业计算工具的重要条件。

手册建议在试行政策之前另存城市，比较不同发展路径。存档在这里不只挽救失败，也支持一种分叉实验：保持同一初始条件，尝试不同分区或预算。这个能力增强了观察，却也使玩家拥有现实治理者难以获得的撤销权；游戏经验因此带有鲜明的媒介条件。[1]

相同的人口数字也可能来自不同城市结构。一个地方道路密集、扩张迅速，另一个依靠更紧凑的布局维持收支，两者不应只因总人口相近就被看成同一成果。观察图层与长期变化，使玩家能够把一个抽象成绩重新分解为空间和制度选择。这样的比较既能在游戏内指导下一步，也能训练人注意模型把什么压缩成了同一个指标。

城市还会把政策效果延后显现。修建新区域时的支出很明确，未来税源和维护负担却需要等待。玩家必须在结果尚未完全出现时继续决定，因而经验既来自确切反馈，也来自对延迟的耐心。因此，规划像一次试探，初期增长之后仍需观察税收能否长期负担维护开支。

# 开放目标与情节式挑战

自由建设没有一条必须达到的唯一结局。玩家可以追求人口规模，也可以经营较小、财政稳定、环境舒适的城市。手册甚至明确说明，更大不自动等于更好。作品允许人们把不同理想带进同一规则框架，再通过运行观察它们是否能够自持。[1]

与此同时，原作也包含有指定状况和目标的场景。它们把玩家放进已有城市的问题中，要求在特定期限和条件下应对危机。自由建设与场景挑战并存，所以用“完全没有目标”概括SimCity并不准确。目标既可能由程序给定，也可能由玩家自行提出。

这种形式使故事主要来自过程。一次扩张、一次电力中断或一场财政危机，可以成为玩家记住的城市史；屏幕上没有必要出现一个始终固定的主角。城市本身具有时间连续性，玩家通过建设与补救承担其中的行动角色。

然而，故事仍依赖模型选择。把污染移到城市一边、用较高地价推动发展，能够形成一种成功叙述；未被模拟的迁移者与社会冲突则很难以同样方式进入成绩。玩家创造自己的城市，也在作者规定的可见指标中理解“自己的成功”。

# 玩具形式中的审美

城市外观由玩家的布局和模型的发展共同生成。规整街区、弯曲岸线、工业边缘与高密度中心，既表达规划选择，也记录随后发生的增长。玩家能够为形状感到满意，即使它尚未取得最高人口；也可能为了财政效率牺牲原先喜欢的轮廓。功能与形式的协商因此进入持续游玩。

地形让这种协商拥有起点。水域、树林和可建设面积构成约束，玩家不能只在完全相同的空白纸上画图。保留一片绿地，既可能是审美偏好，也会与地价、扩张成本和交通路线发生联系。环境没有被简单分成纯装饰和纯功能，两者在同一格地图上重叠。

观看城市自行生长也提供了不同于直接操纵的乐趣。玩家设置条件以后暂时退后，观察空地变成建筑、规模扩大或地区衰落，再决定是否干预。行动与旁观互相交替，使作品既像经营挑战，也像一件能够运转的动态模型。城市的可亲近感来自这种被创造又不完全受控的变化。

这种审美不能用真实建筑照片的标准衡量。小图块省略了生活细节，却让全局关系容易被读出；统计图层又使不可见过程获得空间形态。地图、数字和生长动画共同构成作品的表现语言，而不是等到规划结束以后才补上一层装饰。

# 版本、开放代码与影响边界

不同早期电脑平台需要重新安排菜单、键位、颜色与显示密度。Infogrames手册列出的A. R. Lill程序、J. Lawson图形等分工，属于特定移植工作，不能用来取代Wright的原作设计，也不应被系列品牌遮蔽。移植者参与了作品如何被具体使用的创作。[1]

后来以Micropolis名义开放的Unix版本，为研究城市规则提供了另一组材料。Don Hopkins的发布页明确说明其代码来自约1990年的Unix版本，并为OLPC计划修改；代码许可也保留了对SimCity商标的限制。这份代码保存了原作在后续整理与开放过程中的实现。[3]

开放代码呈现了区域、交通与灾难等过程的计算方式。后来整理的算法与1989年版本之间，存在具体的继承和修改关系；不同平台也会围绕类似工具采用各自的实现。

SimCity的持续意义，在于它把模型当成创作媒介。玩家改变条件，系统产生反馈，人再根据反馈修订自己的城市理想。它既支持设计、观察和叙事，也把规划权、指标政治和模拟边界交给批评。理解这些具体关系，比把它只称作无限自由的造城游戏更能解释作品为何重要。
